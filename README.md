# تطبيق وسيط لحجز مواعيد الأطباء

منصة تربط المريض بالطبيب: بحث حسب المحافظة والتخصص، أوقات متاحة حقيقية، حجز مثبّت،
و**تفاصيل كل حجز تصل واتساب الطبيب فور إتمامه**.

## القرارات المعتمدة

| القرار | الاختيار |
|---|---|
| الدولة | العراق — ١٩ محافظة |
| نقطة البداية | تطبيق جوال أولاً |
| نمط الحجز | النمطان معاً: موعد بوقت محدد **و** رقم دور، يختار الطبيب |
| الخادم وقاعدة البيانات | Node + Fastify + PostgreSQL + Prisma |
| تطبيق المريض | React Native + Expo |
| لوحات المالك والطبيب والسكرتير | Next.js |
| تسجيل الأطباء | **المالك وحده** — لا تسجيل ذاتي |
| إشعار الطبيب | واتساب عبر WhatsApp Cloud API |
| نموذج الربح | عمولة من العيادة على كل مريض يحضر — لا دفع من المريض |
| الخطوط | مستضافة محلياً — لا اعتماد على خادم خارجي قد يبطئ أو يُحجب |

## الحالة

| المرحلة | الحالة |
|---|---|
| ١ — الأساس والمواقع | ✅ |
| ٢ — الحسابات والصلاحيات | ✅ |
| ٣ — ملفات الأطباء والبحث | ✅ |
| ٤ — محرك المواعيد والحجز | ✅ |
| ٥ — لوحة الطبيب | ✅ (لوحة السكرتير المنفصلة ناقصة) |
| ٦ — الإشعارات والتذكيرات | ✅ |
| ٧ — لوحة المالك | ✅ |

**الناقص:** قوالب واتساب معتمدة من ميتا، وبناء نسخ المتاجر — كلاهما يحتاج
حسابات باسمك: ميتا للأعمال، وحساب مطوّر في آبل وجوجل.

## مساران للدخول، لا مسار واحد

```
المريض                    رقم هاتف + رمز تحقق، بلا باسوورد إطلاقاً
الطبيب والسكرتير والمالك   إيميل + باسوورد ينشئهما المالك
```

**لا يوجد تسجيل ذاتي للأطباء.** المالك ينشئ الحساب فيُولَّد باسوورد أولي يظهر له مرة
واحدة ليسلّمه للطبيب، ثم يُلزَم الطبيب بتغييره أول دخول قبل أن يستطيع فعل أي شيء —
وإلا بقي باسوورد يعرفه شخصان. أثر جانبي مفيد: كل طبيب على المنصة موثّق بحكم أن المالك
أدخله بنفسه، وهذا أقوى في بناء الثقة من مراجعة وثائق يرفعها مجهول.

## تحويل الحجز إلى واتساب الطبيب

فور إتمام المريض بياناته تُرسل تفاصيل الحجز إلى رقم واتساب الطبيب:

```
🗓 حجز جديد

المريض: علي حسن
الهاتف: 0770 998 8776
الموعد: الأحد، ٦ أيلول ٢٠٢٦ — الدور ١ بين ٤:٠٠ م و٧:٠٠ م
العيادة: عيادة النور للأطفال
الرقم المرجعي: EK9-ELJ

ملاحظة المريض: الطفل عنده حرارة منذ يومين
```

**فشل الواتساب لا يُفشل الحجز.** الرسالة تُسجَّل صفاً في `notification_logs` ثم تُرسل بعد
نجاح الحجز؛ إن سقط الإرسال بقيت في الطابور لإعادة المحاولة، ولم يخسر المريض موعده لأن
واتساب كان متعطلاً.

### ما يلزم لتشغيل الإرسال الحقيقي

الطريق الرسمي الوحيد هو **WhatsApp Cloud API** من ميتا، ويتطلب:

1. حساب Meta Business موثّق
2. **رقم هاتف مخصص للـ API** — لا يعود صالحاً لتطبيق واتساب العادي بعد ربطه
3. اعتماد قالبَي `new_booking` و`booking_cancelled` من ميتا بالعربية — واتساب لا يسمح
   بإرسال نص حر لمن لم يراسلك خلال ٢٤ ساعة، والطبيب لن يراسل المنصة أصلاً
4. تعيين `WHATSAPP_TOKEN` و`WHATSAPP_PHONE_NUMBER_ID`

بدون هذه المتغيرات يعمل مزوّد بديل يطبع الرسالة في الطرفية مع رابط `wa.me` جاهز — يصلح
للتطوير وكحل يدوي مؤقت.

> المكتبات غير الرسمية (`whatsapp-web.js` وأمثالها) تخالف شروط واتساب وتؤدي إلى حظر
> الرقم. لم تُستعمل ولا يُنصح بها.

## الواجهات

| الواجهة | لمن | ماذا فيها |
|---|---|---|
| **تطبيق الجوال** (`mobile/`) | المريض | أندرويد وآيفون — المحافظة والتخصصات والأطباء والحجز وحجوزاتي |
| `/` (ويب) | المريض | نفس مسار الحجز، لمن يفضّل المتصفح |
| `/doctor` | الطبيب | مرضى اليوم وتأشير الحضور · تحديد أيام الدوام وساعاتها ونمط الحجز · الإجازات وتعطيل الفترات |
| `/owner` | المالك | ملخص كامل وتنبيهات لما يحتاج تدخّله · تسجيل الأطباء وإنشاء حساباتهم · سجل رسائل الواتساب |

الطبيب والسكرتير والمالك يستعملون الويب لا التطبيق — السكرتير يعمل على حاسوب في
العيادة، وتحرير الجداول أسهل بكثير على شاشة كبيرة.

**الأوقات المتاحة تُحسب لحظة العرض** من ثلاثة مصادر تُدمج معاً:

```
قالب دوام الطبيب  −  إجازاته واستثناءاته  −  ما حُجز فعلاً
```

فما إن يحجز مريض وقتاً حتى يختفي من شاشة الجميع، ويظهر للطبيب في لوحته مؤشَّراً
كمحجوز لا مخفياً. والإلغاء يعيده للظهور فوراً. لا فترات مولَّدة مخزَّنة مسبقاً،
فتعديل الطبيب لجدوله ينعكس على المرضى في اللحظة نفسها.

## التشغيل

حساب المالك يصير حسابك من أول تشغيل، والباسوورد عشرة أحرف فأكثر:

```bash
OWNER_EMAIL=you@example.com OWNER_PASSWORD=ChangeMe12345 bash setup.sh
```

يشغّل قاعدة البيانات بدوكر، وينشئ `api/.env` بسر توقيع عشوائي، ويعبّئ
المحافظات والتخصصات وحساب المالك، ويثبّت اعتماديات المشاريع الثلاثة.

بلا المتغيّرين يستعمل `owner@mawid.iq` / `MawidOwner2026`. لو مرّرتهما وكان
`api/.env` موجوداً من تشغيل سابق، يُحدَّث سطرا المالك وحدهما ويبقى سرّ التوقيع
ورابط القاعدة كما هما.

ثم كلٌّ في **نافذة طرفية مستقلة** — الثلاثة معاً في نافذة واحدة لا تعمل، لأن
كل أمر يبقى مشغّلاً ولأن `cd` نسبيّ فيفشل الثاني والثالث:

الخادم على ٣٠٠٠:

```bash
cd ~/hhj/api && npm run dev
```

اللوحات على ٣٠٠١:

```bash
cd ~/hhj/web && npm run dev
```

التطبيق — يطبع رمز QR تمسحه بـExpo Go:

```bash
cd ~/hhj/mobile && npm start
```

> لا تضع تعليقاً عربياً داخل سطر أوامر: نسخه يجرّ معه علامات اتجاه غير مرئية
> تكسر الأمر عند اللصق.

**دخول المالك:** ما وضعته في `OWNER_EMAIL` و`OWNER_PASSWORD` — ويُطلب تغيير
الباسوورد أول دخول.

### إذا رفض الخادم الإقلاع

`JWT_SECRET مفقود أو أقصر من ٣٢ خانة` — ملفّ `api/.env` ناقص، غالباً من تشغيلٍ
سابق انقطع في منتصفه. يُصلَح بأمر واحد يولّد ما ينقص ولا يمسّ ما هو سليم:

```bash
cd ~/hhj/api && npm run env:fix
```

`تعذّر الاتصال بقاعدة البيانات` — القاعدة مطفأة أو منفذها غير الذي في
`DATABASE_URL`:

```bash
cd ~/hhj && docker compose up -d
```

### إن أُغلق حساب المالك بوجهك

بعد تغيير الباسوورد من الواجهة يبقى `api/.env` على القيمة القديمة، والتعبئة لا
تمسّ باسوورد حسابٍ موجود عمداً. فإن نسيت الجديد، اكتب ما تريد في
`OWNER_PASSWORD` داخل `api/.env` ثم:

```bash
cd ~/hhj/api && npm run owner:reset
```

يعيد الباسوورد إلى ما في الملف ويفكّ أي قفلٍ من محاولات فاشلة. لا يعمل إلا على
حساب المالك، ولا يمسّ حساباً آخر.

### بيانات تجريبية

`db:seed` يعبّئ المرجعيات فقط — المحافظات والتخصصات — فيفتح التطبيق فارغاً بلا
طبيب واحد. لملئه بما يكفي لتجربة كل شاشة:

```bash
cd api && npm run db:demo
```

اثنا عشر طبيباً في بغداد بتخصصات وعيادات ودوام وتقييمات، بنمطَي الحجز معاً.
الأمر لا يكرّر ما أضافه سابقاً، و`npm run db:demo -- --clean` يحذفهم أولاً.
كلهم موسومون بـ`demo.mawid` في البريد فلا يختلطون بأطباء حقيقيين، ودخول أيٍّ
منهم: `<التخصص>.demo.mawid.iq` / `DemoDoctor2026`.

### تشغيله بجانب مشروع آخر

كل المنافذ قابلة للتغيير، وهذا يهمّ إن كان عندك مشروع آخر يشغّل ٣٠٠٠ أو ٥٤٣٢
أو ٨٠٨١ — والأخير منفذ ميترو الافتراضي لكل مشروع React Native:

| ماذا | المتغيّر | الافتراضي |
|---|---|---|
| الخادم | `PORT` في `api/.env` | ٣٠٠٠ |
| لوحات الويب | `WEB_PORT` | ٣٠٠١ |
| نسخة التطبيق المصدَّرة | `DIST_PORT` | ٣٠٠٢ |
| قاعدة البيانات | `DB_PORT` قبل `docker compose` | ٥٤٣٢ |
| ميترو | `npm start -- --port 8082` | ٨٠٨١ |
| عنوان الخادم في التطبيق | `EXPO_PUBLIC_API_PORT` | ٣٠٠٠ |

مثال كامل بمنافذ لا تصطدم:

```bash
DB_PORT=5433 docker compose up -d
```

ثم في `api/.env`: `PORT=3010`، و`WEB_ORIGIN` يذكر ٣٠١١، و`DATABASE_URL` على
٥٤٣٣. وكلٌّ في نافذة:

```bash
cd ~/hhj/api && npm run dev
```

```bash
cd ~/hhj/web && WEB_PORT=3011 npm run dev
```

```bash
cd ~/hhj/mobile && EXPO_PUBLIC_API_PORT=3010 npm start -- --port 8082
```

المنفذان اللذان يجب أن يتطابقا: `WEB_ORIGIN` في `api/.env` يجب أن يذكر منفذ
الويب، و`DATABASE_URL` يجب أن يذكر `DB_PORT` نفسه.

### تجربة التطبيق على هاتفك

١. ثبّت **Expo Go** من متجر هاتفك.
٢. اربط الهاتف والحاسوب بنفس شبكة الواي فاي.
٣. `cd ~/hhj/mobile && npm start` ثم امسح رمز QR الظاهر.

التطبيق **يستنتج عنوان حاسوبك تلقائياً** من خادم Expo ويستعمل المنفذ ٣٠٠٠،
فلا تحتاج معرفة عنوان الشبكة. لو كان الخادم على جهاز أو منفذ آخر، عيّن
`EXPO_PUBLIC_API_URL` في `mobile/.env`.

> لن يعمل `localhost` مكتوباً بيدك: داخل الهاتف يشير إلى الهاتف نفسه لا إلى حاسوبك.

**إن فتح التطبيق ولم تصله بيانات على ويندوز:** جدار الحماية يحجب المنفذ عند
أول تشغيل. الخادم يطبع عنوان حاسوبك على الشبكة عند إقلاعه — افتحه من متصفّح
الهاتف: إن ظهرت صفحة فالمنفذ مفتوح والعطل في مكان آخر، وإن لم تظهر فاسمح
لـNode.js في Windows Defender Firewall للشبكات الخاصة.

#### تطبيق خاص بك بدل Expo Go

Expo Go تطبيقٌ واحد يشغّل مشاريع كثيرة، فيدعم إصداراً واحداً فقط، ومتجر
جوجل يعطي كل هاتف أحدث نسخةٍ تناسب أندرويد الذي عليه — فقد لا يصلك الإصدار
الذي يلزم مهما حدّثت. البناء الخاص يزيل هذا الشرط من الطريق: تطبيقٌ باسم
المشروع وأيقونته، ينزل مرة ويعمل على أي أندرويد.

يحتاج **حساب Expo مجاني**. البناء على سحابتهم فلا يلزمك Android Studio.

```bash
cd ~/hhj/mobile && npx eas login
```

```bash
cd ~/hhj/mobile && npm run build:dev
```

أول مرة يسألك عن إنشاء مشروع على حسابك وعن مفتاح التوقيع — وافق على
الافتراضي في الاثنين. البناء يستغرق نحو ربع ساعة، وينتهي برابط تفتحه من
**هاتفك** فينزل ملف APK. ثبّته وستُطالَب بالسماح بالتثبيت من مصدر غير
المتجر — هذا متوقّع لأنّ الملف منك لا من جوجل.

بعدها كالمعتاد:

```bash
cd ~/hhj/mobile && npm start
```

وتفتح التطبيق المثبَّت لا Expo Go. يجد الخادم بنفسه كما كان، والتعديلات
تصلك فوراً كما كانت. ولا تعيد البناء إلا إذا أُضيفت حزمة أصيلة جديدة.

**نسخة تعمل وحدها بلا حاسوب:** `npm run build:apk` يبني APK يحمل الشفرة
داخله. لكنّه لا يجد الخادم بنفسه — لا خادم تطوير يسأله — فأضف عنوان حاسوبك
في `mobile/eas.json` ضمن `preview` قبل البناء:

```json
preview: { env: { EXPO_PUBLIC_API_URL: http://192.168.1.23:3000 } }
```

#### إن رفض Expo Go المشروع

رسالة `Incompatible SDK version` تعني أنّ Expo Go على هاتفك أقدم من إصدار
المشروع. متجر جوجل يعطي كل هاتف أحدث نسخة تناسب أندرويد الذي عليه، فقد تكون
«الأحدث عندك» أقدم من «الأحدث الموجود».

ريثما يُحسم ذلك، افتح التطبيق من **متصفّح الهاتف** — نفس الشاشات والمنطق
والاتجاه، بلا Expo Go. على الحاسوب:

```bash
cd ~/hhj/mobile && npm run export:web
```

```bash
cd ~/hhj/mobile && npm run serve:web
```

ثم افتح في متصفّح الهاتف عنوان حاسوبك الذي يطبعه الخادم، بالمنفذ ٣٠٠٢ —
مثلاً `http://192.168.1.23:3002`. يستنتج التطبيق عنوان الخادم من عنوان
الصفحة نفسها، فلا إعداد.

ما لا يغطيه هذا الطريق: الحافظة الآمنة، الإشعارات، وشاشة الإقلاع الأصيلة.

**لتجربة كل شيء بسرعة:** ادخل لوحة المالك على `localhost:3001` ← سجّل طبيباً
← أنشئ عيادة واربطها به ← ادخل بحساب الطبيب وحدد أوقات دوامه ← افتح التطبيق
على هاتفك وستجده.

أول دخول: بالإيميل والباسوورد اللذين وضعتهما في `OWNER_EMAIL` و`OWNER_PASSWORD`،
وسيُطلب منك تغيير الباسوورد قبل أي شيء. ثم سجّل أول طبيب من تبويب «الأطباء».

## الاختبارات

فحص الأنواع و٥٥ اختباراً على قاعدة بيانات حقيقية:

```bash
cd ~/hhj/api && npm run verify
cd ~/hhj/web && npm run typecheck
cd ~/hhj/mobile && npm run typecheck
```

المسار الكامل في متصفح حقيقي — كلا الاختبارين يجهّز بياناته بنفسه:

```bash
cd ~/hhj/web && OWNER_EMAIL=... OWNER_PASSWORD=... npm run e2e
```

```bash
cd ~/hhj/mobile && npm run export:web && npm run serve:web &
cd ~/hhj/mobile && OWNER_EMAIL=... OWNER_PASSWORD=... npm run e2e
```

اختبارات المتصفّح تنزّل متصفّحها بنفسها؛ إن كان عندك واحد جاهز مرّره بـ
`CHROME_PATH=/path/to/chromium`. ومنفذ ٣٠٠٢ مسموح في `WEB_ORIGIN` أصلاً لأن
اختبار الجوال يقدّم النسخة المصدَّرة عليه.

اختبار التطبيق يمر عبر نسخة الويب المصدَّرة، لأن `react-native-web` يشغّل نفس
شفرة الشاشات والمكوّنات. ما لا يغطيه: ما يخص المنصّة وحدها — الحافظة الآمنة،
الإشعارات، وسلوك لوحة المفاتيح — وهذه تحتاج جهازاً أو محاكياً.

## التذكيرات والعمولات والتقييمات

**التذكيران** يُرسلان قبل الموعد بيوم وبساعتين عبر واتساب. مجدوِل داخل الخادم
يفحص كل عشر دقائق. لا يُرسل تذكير مرتين مهما تداخلت التشغيلات: القيد الفريد على
`(appointmentId, template)` يرفض الصف الثاني — لا فحصٌ في الكود، لأن أي فحص
ينكسر عند تشغيلين متزامنين.

**العمولة** هي نموذج الربح: المنصة تأخذ مبلغاً من العيادة عن كل مريض **يحضر
فعلاً**. لا دفع من المريض إطلاقاً — يدفع أجرته للعيادة كما اعتاد.

الربط بالحضور لا بالحجز مقصود: العيادة ترفض الدفع عن مريض لم يأتِ، وربط العمولة
بالحضور يجعل مصلحة المنصة ومصلحة العيادة واحدة — كلاهما يريد مريضاً يصل لا حجزاً
على الورق. تُسجَّل العمولة صفاً لكل زيارة لا مجموعاً محسوباً، فيستطيع المالك أن
يبيّن للعيادة على أي مريض بالضبط يطالبها. وتصحيح تأشير خاطئ إلى «لم يحضر» يُلغيها.

**التقييم** لا يكتبه إلا من حضر وأُشِّر انتهاء كشفه. الدرجة تُحتسب فوراً في متوسط
الطبيب، والتعليق ينتظر مراجعة المالك، ويظهر بالاسم الأول فقط.

## منع الحجز المزدوج

إذا حجز مريضان نفس الوقت مرة واحدة أمام طبيب، تفقد الطبيب. التحقق في الكود لا يكفي: بين
قراءة «هذا الوقت فارغ» وكتابة الحجز فجوة تمرّ منها ضغطتان متزامنتان.

الحماية قيد فريد على `(doctorClinicId, slotStart, queueNumber, lockKey)`. الحقل `lockKey`
يساوي `true` ما دام الحجز يشغل المكان، ويصبح `NULL` عند الإلغاء — وبما أن بوستغرس يعتبر
قيم `NULL` مختلفة في القيود الفريدة، يتحرر المكان لغيره بينما يبقى صف الحجز الملغى
محفوظاً في السجل.

## التحقق

`npm run verify` — فحص أنواع + ١٨ اختباراً على قاعدة بيانات حقيقية:

```
الحجز المزدوج (٤)
  ✔ نمط الوقت المحدد يرفض حجز نفس الفترة مرتين
  ✔ الإلغاء يحرّر الفترة ويُبقي سجل الملغى
  ✔ نمط رقم الدور يرفض تكرار نفس الرقم ويقبل التالي
  ✔ ست محاولات متزامنة ⇒ حجز واحد فقط ينجح

حسابات المالك والواتساب (١٤)
  ✔ كل صيغ الرقم العراقي تُطبَّع إلى صيغة واحدة
  ✔ رقم الهاتف يُعرض بصيغة عراقية مقروءة وقابلة للنقر
  ✔ المالك ينشئ حساب الطبيب بإيميل وباسوورد أولي
  ✔ الباسوورد لا يُخزَّن نصاً في قاعدة البيانات
  ✔ الطبيب يدخل بالباسوورد الأولي ويُطلب منه تغييره
  ✔ بعد التغيير يدخل بالباسوورد الجديد ولا يعمل القديم
  ✔ الحساب يُقفل مؤقتاً بعد خمس محاولات فاشلة
  ✔ إعادة تعيين الباسوورد من المالك تفك القفل وتُلزم بتغيير جديد
  ✔ تفاصيل الحجز تُرسل لواتساب الطبيب
  ✔ وسائط القالب خالية من الأسطر الجديدة
  ✔ تعطّل واتساب لا يُفشل الحجز
  ✔ إعادة المحاولة توصّل ما سقط
  ✔ إيقاف الواتساب لطبيب يمنع الإرسال دون تعطيل الحجز
  ✔ المزوّد الاحتياطي يسجّل الرسالة ويعطي رابط wa.me

محرك الأوقات (١٤)
  ✔ الأيام التي حددها الطبيب فقط هي التي تفتح للحجز
  ✔ الفترات تُولَّد بمدة الكشف التي حددها الطبيب
  ✔ الوقت المحجوز يختفي من شاشة المريض
  ✔ الطبيب يرى الفترة محجوزة لا مخفية
  ✔ محاولة حجز وقت محجوز تُرفض
  ✔ إلغاء الحجز يعيد الوقت للظهور للمرضى
  ✔ الحجز في يوم لا يداوم فيه الطبيب مرفوض
  ✔ الحجز في وقت لا يقع على شبكة الفترات مرفوض
  ✔ إجازة الطبيب تغلق اليوم كاملاً
  ✔ إغلاق فترة جزئية يحذف ساعتها فقط
  ✔ نمط رقم الدور: الأرقام تتسلسل والفترة الممتلئة تُخفى
  ✔ الفترات التي مضت لا تظهر للحجز
  ✔ لوحة الطبيب تعرض مرضى اليوم بالترتيب
  ✔ التخصص يعرض عدد أطبائه والبحث يجد الطبيب مع أقرب موعد
```

وفي متصفح حقيقي (`npm run e2e`): الطبيبة تحدد أوقاتها ← المريض يرى الشاغر فقط ←
يحجز ← الوقت يختفي ← الطبيبة ترى المريض مع ملاحظته.

## ملاحظات

- التقسيمات الإدارية تتغير — راجع قوائم الأقضية قبل الإطلاق. كلها قابلة للتعديل من لوحة
  المالك دون لمس الكود.
- أرقام الهواتف تُقبل بكل صيغها (`07701234567` · `+9647701234567` · `٠٧٧٠١٢٣٤٥٦٧`)
  وتُخزَّن بصيغة واحدة — وإلا تكرر الحساب الواحد بأشكال مختلفة.
- الأوقات كلها تُخزَّن بتوقيت عالمي وتُعرض بتوقيت العيادة (`Asia/Baghdad`).
- لا يخزّن النظام تشخيصات ولا تقارير طبية — وسيط حجز فقط، وهذا قرار مقصود.
- `npm audit` يبلّغ عن ثغرة في `deepmerge-ts` عبر أداة Prisma السطرية. هي اعتمادية
  تطوير لا تدخل الإنتاج، ولا تتوفر نسخة مصحَّحة بعد.
- الهوية زمرّدي عميق `#0E5140` وذهبي `#8B6316` للتمييز. الدرجات كلها في
  `mobile/src/theme.ts` و`web/src/app/globals.css` وهما متطابقان، وكل تباين نصّ
  فيهما يعبر معيار WCAG AA.
- التطبيق مبنيّ على كيت «Doctor Appointment App UI Kit» في فيغما: تخطيطه
  ولوحه الرمادي وأساسه الكحلي `#1C2A3A`. الزمرّدي `#0E5140` بقي علامةً فقط —
  أيقونة التطبيق وشاشة البداية والمربّع في ترويسة الرئيسية.
  الخطوط والاتجاه العربي من عندنا لا من الكيت.
- الأيقونات وشاشة البداية مولّدة من تعريف واحد في `mobile/scripts/generate-icons.mjs`
  (حرف «م» أبيض فوق تدرّج زمرّدي، والكلمة بخط ريم كوفي). شغّله بعد أي تغيير في
  ألوان الهوية: `node scripts/generate-icons.mjs` — ويكتب أصول الجوال والويب معاً.
- أيقونات التخصصات الـ٢٨ مرسومة يدوياً في `mobile/src/components/specialty-paths.ts`.
  المكتبات الجاهزة تعطي أيقونة «مستشفى» واحدة للجميع، والمريض يميّز عيادة العيون
  من الأسنان بالشكل قبل أن يقرأ. نسخة الويب مولَّدة:
  `cd mobile && node scripts/sync-specialty-icons.mjs` (و`--check` يفشل إن افترقتا).
- الخطوط مستضافة في `web/public/fonts` و`mobile/assets/fonts` برخصة SIL OFL.
  الاعتماد على خادم خطوط خارجي يعني ظهور التطبيق بخط احتياطي إن كان بطيئاً أو محجوباً.
- التطبيق يخزّن رموز الدخول في الحافظة الآمنة للجهاز (Keychain على آيفون،
  Keystore على أندرويد) لا في تخزين عادي — لأنها تكافئ كلمة مرور.
- `npm audit` في `mobile/` يبلّغ عن ثغرات متوسطة في أدوات بناء Expo لا في شفرة
  التطبيق، وإصلاحها يعني تنزيل نسخة قديمة كاسرة.
