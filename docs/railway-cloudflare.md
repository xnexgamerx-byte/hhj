# الانتقال إلى Railway وCloudflare

دليلٌ خطوةً بخطوة لنقل دكتور صحتي من Render:

| الجزء | الآن | بعد الانتقال |
|---|---|---|
| الدومين | — | Cloudflare |
| اللوحات وموقع الحجز (`web/`) | Render | Cloudflare Pages، مجاناً |
| نسخة التطبيق للويب (`mobile/`) | Render | Cloudflare Pages، مجاناً |
| الخادم (`api/`) | Render | Railway |
| قاعدة البيانات | Render | Railway، ونسخةٌ احتياطية مشفّرة كل ليلة في GitHub |
| الصور | قرص Render | قرصٌ دائم على Railway |

**Render يبقى يعمل حتى الخطوة الأخيرة.** الجديد يُبنى ويُجرَّب بجانبه، ولا يتحوّل
المستخدمون إلا بعد التأكد. ومن توقّف في منتصف الطريق لم يخسر شيئاً.

**الكلفة:** خطة Hobby في Railway بخمسة دولارات شهرياً، وتشمل خمسة دولارات من
الاستهلاك. وتقديري لهذا الحجم (الخادم والقاعدة والصور) أن الفاتورة تبقى بين ٥ و٧
دولارات. وCloudflare Pages مجانية، ويبقى ثمن الدومين السنوي.

في الأمثلة `example.com` مكان دومينك.

## ما يلزمك قبل البدء

- **حساب Cloudflare ودومين:** تشتريه من Cloudflare نفسها، أو من أي مكان ثم تنقل
  خوادم أسمائه (nameservers) إليها.
- **حساب Railway:** سجّل بحساب GitHub نفسه، فيرى المستودع مباشرة. الفترة التجريبية
  (٣٠ يوماً أو ٥ دولارات) تكفي للتجربة، واشترك في خطة Hobby قبل التحويل — وإلا
  توقّفت الخدمات بانتهائها.
- **لوحة Render:** منها تنسخ سرّ الدخول ورابط القاعدة ومتغيّرَي الواتساب.

## ١. حدّ الإنفاق

Railway ← صفحة **Usage** في إعدادات حسابك ← **Usage Limits**:

| الحدّ | القيمة | ماذا يفعل |
|---|---|---|
| Custom email alert | `8` | بريدٌ ينبّهك، والخدمات تعمل كما هي |
| Hard limit | `15` | يوقف كل شيء — لذلك أعلى من المتوقَّع بفسحة |

## ٢. القاعدة على Railway

١. **New Project** ← **Database** ← **PostgreSQL**. إن خُيّرت في الإصدار فالأحدث.

٢. على خدمة **Postgres** ← **Settings** ← **Region:** ‏EU West (Amsterdam) — أقرب
   مناطقها إلى العراق.

   تبويب **Backups** فيها لخطة Pro وحدها (٢٠ دولاراً شهرياً)، فلا تحتاجه: النسخ
   الاحتياطي من GitHub كل ليلة، مجاناً — القسم ٩.

## ٣. الخادم على Railway

١. في المشروع نفسه: **Create** (أو **+ New**) ← **GitHub Repo** ← `xnexgamerx-byte/hhj`. قد يبدأ
   بناءٌ أول ويفشل قبل الإعدادات أدناه — لا بأس، يُعاد بعدها.

٢. على الخدمة الجديدة ← **Settings**:

| الإعداد | القيمة |
|---|---|
| Source ← Branch | `claude/doctor-booking-app-aary82` |
| Source ← Root Directory | `/api` |
| Build ← Watch Paths | `/api/**` |
| Deploy ← Region | EU West (Amsterdam) |
| Deploy ← Healthcheck Path | `/health` |

   ‏Railway تجد `api/Dockerfile` فتبني منه وحدها. ومسار المراقبة يجعل تعديلات
   اللوحات والتطبيق لا تعيد نشر الخادم.

٣. **القرص الدائم للصور:** زرّ الفأرة الأيمن على مربّع الخدمة ← **Attach Volume** ←
   المسار `/data/uploads`.
   الخادم يرفض الإقلاع بلا هذا القرص — صورٌ تُكتب في الحاوية تُمحى مع أول نشر.

٤. **Variables** ← **Raw Editor** ← الصق هذا بعد تبديل `example.com` وسرّ الدخول:

```
DATABASE_URL=${{Postgres.DATABASE_URL}}
JWT_SECRET=انسخه-من-Render
WEB_ORIGIN=https://example.com,https://www.example.com,https://app.example.com
UPLOADS_SOURCE=https://doctorsehti-api.onrender.com
RAILWAY_DEPLOYMENT_DRAINING_SECONDS=10
```

| المتغيّر | لماذا |
|---|---|
| `DATABASE_URL` | يربط الخادم بالقاعدة داخل Railway. إن سمّيتَ خدمة القاعدة غير `Postgres` فاكتب اسمها |
| `JWT_SECRET` | من Render: خدمة `doctorsehti-api` ← **Environment**. هو نفسه يُبقي من سجّل دخوله داخلاً |
| `WEB_ORIGIN` | المواقع المسموح لها بمكالمة الخادم من المتصفّح. وللتجربة على عنوان Cloudflare قبل ربط دومينك أضف إليه عنوانَي المشروعين، مثل `https://doctorsehti-web.pages.dev` |
| `UPLOADS_SOURCE` | أثناء الانتقال فقط: عند كل إقلاعٍ يسحب الخادم من Render كل صورةٍ تذكرها القاعدة ولم تصله بعد |
| `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` | عشر ثوانٍ يُنهي فيها الخادم ما بيده قبل كل نشر. ‏Railway تقطعه فوراً بدونه |

   **ولا تضف متغيّرَي واتساب الآن:** من القاعدة المنقولة يرسل الخادم تذكيرات
   المواعيد، وRender يرسلها كذلك — فيصل المريضَ كلُّ تذكيرٍ مرّتين. يُضافان لحظة
   التحويل، وحتى ذلك الحين تُكتب الرسائل في سجلّ الخادم ولا تُرسل.

   ثم **Deploy**. البناء الأول بضع دقائق.

٥. **Settings** ← **Networking** ← **Custom Domain** ← `api.example.com`. إن سُئلت عن
   المنفذ فـ`8080`. تعرض Railway سجلَّين، فأضفهما كما هما في Cloudflare ← **DNS**:

| Type | Name | Content | Proxy status |
|---|---|---|---|
| CNAME | `api` | ما تعرضه Railway | **DNS only** (السحابة رمادية) |
| TXT | ما تعرضه Railway | ما تعرضه Railway | — |

   رماديةً لا برتقالية: Railway تأخذ شهادة HTTPS بنفسها، ويصل الخادمَ عنوانُ كل
   مستخدمٍ الحقيقي — وحدّ محاولات الدخول يُحسب به.

٦. بعد دقائق افتح `https://api.example.com/health`. ظهور `{"ok":true}` يعني أن
   الدومين تحقّق والشهادة صدرت والخادم جاهز.

## ٤. اللوحات وموقع الحجز على Cloudflare Pages

Cloudflare ← **Workers & Pages** ← **Create** ← **Pages** ← **Connect to Git** ←
المستودع `xnexgamerx-byte/hhj`.

**Pages لا Workers:** صفحة Create تفتح على Workers أولاً. إن رأيت خانة **Deploy
command** فيها `npx wrangler deploy` فأنت في Workers — ارجع واختر Pages.

| الإعداد | القيمة |
|---|---|
| Project name | أي اسم، مثل `doctorsehti-web` |
| Production branch | `claude/doctor-booking-app-aary82` |
| Root directory | `web` |
| Build command | `npm run build:static` |
| Build output directory | `out` |
| Environment variables | `NEXT_PUBLIC_API_URL` = `https://api.example.com` · `NODE_VERSION` = `22` |

ثم **Custom domains**: `example.com` و`www.example.com`.

البناء يرفض أن يكمل إن غاب `NEXT_PUBLIC_API_URL` أو لم يبدأ بـ`https://`: العنوان
يُكتب داخل الملفّات، وموقعٌ لا يجد خادمه أسوأ من بناءٍ فاشل. وكل دمجٍ في الفرع
الرئيسي يعيد البناء والنشر وحده.

## ٥. نسخة التطبيق للويب على Cloudflare Pages

مشروعٌ ثانٍ بالطريقة نفسها:

| الإعداد | القيمة |
|---|---|
| Project name | أي اسم، مثل `doctorsehti-app` |
| Production branch | `claude/doctor-booking-app-aary82` |
| Root directory | `mobile` |
| Build command | `npx expo export --platform web` |
| Build output directory | `dist` |
| Environment variables | `EXPO_PUBLIC_API_URL` = `https://api.example.com` · `NODE_VERSION` = `22` |

ثم **Custom domains**: `app.example.com`. التطبيق صفحةٌ واحدة، وCloudflare تخدمها
لكل رابطٍ بداخله تلقائياً.

## ٦. نقل البيانات — تجربة أولى

النقل زرٌّ في GitHub يعمل على خوادمه، فلا تثبّت شيئاً على جهازك. يلزمه رابطا
القاعدتين، يُحفظان سرَّين في المستودع:

| السرّ | من أين |
|---|---|
| `SOURCE_DATABASE_URL` | Render: صفحة قاعدة البيانات ← **Connect** ← **External** |
| `TARGET_DATABASE_URL` | Railway: خدمة **Postgres** ← **Variables** ← `DATABASE_PUBLIC_URL` |

GitHub ← **Settings** ← **Secrets and variables** ← **Actions** ← **New repository
secret**، مرّةً لكلٍّ منهما. ثم:

١. **Actions** ← «نقل قاعدة البيانات إلى Railway» ← **Run workflow** ← اكتب `نعم` ←
   **Run workflow**. دقيقة أو اثنتان.

٢. بعد العلامة الخضراء: Railway ← خدمة الخادم ← **Deployments** ← ⋮ ← **Restart**.
   الخادم عند إقلاعه يسحب الصور من Render، ويتحقق من كل صورةٍ ببصمة محتواها.

٣. جرّب: ادخل `https://example.com/login` بحساب المالك **بباسووردك على Render** —
   الحسابات انتقلت كما هي — وتصفّح الأطباء والصور واللافتات، واحجز موعداً تجريبياً
   من `https://app.example.com`.

- النقل يمحو ما في قاعدة Railway ويضع مكانه ما في Render الآن، ولا يكتب في Render
  شيئاً. والمحو والإحلال معاً أو لا شيء: إن فشل في منتصفه بقيت Railway كما كانت.
  فتكراره آمن.
- المستودع عامّ، وسجلّ التشغيل يراه أيّ أحد — لذلك لا يُطبع فيه شيءٌ من البيانات،
  وعنوانا القاعدتين محجوبان.
- تنبيهٌ أصفر في آخره بأن جداول «تغيّرت في Render أثناء النقل» طبيعيٌّ الآن: Render
  يعمل ويُكتب فيه. ما يُكتب فيه بعد النسخة لا ينتقل، لذلك يُعاد النقل لحظة التحويل.

## ٧. نسخة APK الجديدة

GitHub ← **Settings** ← **Secrets and variables** ← **Actions** ← **Variables** ←
**New repository variable**: الاسم `API_URL` والقيمة `https://api.example.com`. ثم
**Actions** ← «بناء نسخة أندرويد للتجربة» ← **Run workflow**.

جهّزها ولا توزّعها بعد: من يثبّتها قبل التحويل يكتب على الخادم الجديد، والنقل
الأخير يضع مكان ما كتب.

## ٨. التحويل

في ساعةٍ هادئة — منتصف الليل في بغداد مثلاً — ولا ترفع صوراً من لوحة المالك من
أول هذه الخطوات إلى آخرها:

١. **آخر تجربة:** شغّل زرّ النقل، ثم **Restart** للخادم في Railway. هكذا يأخذ كل صورةٍ
   رُفعت حتى الآن، وRender ما زال يعطيها.

٢. **أوقف الكتابة على Render:** خدمة `doctorsehti-api` ← **Settings** ← **Suspend**.
   يتوقف معها التطبيق القديم والمواقع القديمة، فلا يُكتب شيءٌ يضيع. والقاعدة خدمةٌ
   منفصلة تبقى تعمل، ومنها يُنسخ.

٣. **النقل الأخير:** شغّل زرّ النقل مرّةً أخيرة. آخره يجب أن يقول «✔ تطابقت الجداول
   كلّها». إن قال غير ذلك فخادم Render لم يتوقف — تأكّد ثم أعده.

٤. **الواتساب:** Railway ← خدمة الخادم ← **Variables**: أضف `WHATSAPP_TOKEN` و
   `WHATSAPP_PHONE_NUMBER_ID` من Render (خدمة `doctorsehti-api` ← **Environment**) ثم
   **Deploy**. التذكيرات تخرج من Railway وحدها الآن.

٥. وزّع نسخة APK الجديدة، وأعطِ الجميع عناوين المواقع الجديدة.

٦. فعّل النسخ الاحتياطي الليلي (القسم ٩) إن لم تفعل في التجربة.

٧. أبقِ Render موقوفاً لا محذوفاً أسبوعاً — شبكة أمان. ثم احذف خدماته ومعها القاعدة
   ليتوقف الدفع، واحذف من Railway متغيّر `UPLOADS_SOURCE`، ومن GitHub سرَّي النقل
   `SOURCE_DATABASE_URL` و`TARGET_DATABASE_URL` (لا سرَّي النسخ الاحتياطي).

**إن ساء شيءٌ لحظة التحويل:** Render ← `doctorsehti-api` ← **Resume**. لم يُمسّ فيه
شيء، فيعود كل شيءٍ كما كان، وتعيد المحاولة يوماً آخر.

## ٩. النسخ الاحتياطي

نسخ Railway الاحتياطية لخطة Pro وحدها (٢٠ دولاراً شهرياً). فالمستودع ينسخ القاعدة
وصورها بنفسه كل ليلة ٣:٣٠ بتوقيت بغداد، مجاناً، ويحفظها في GitHub مشفّرة: القاعدة
تسعين يوماً، والصور أربعة عشر.

**الإعداد مرّةً واحدة** — سرّان في GitHub ← **Settings** ← **Secrets and variables**
← **Actions** ← **New repository secret**:

| السرّ | القيمة |
|---|---|
| `BACKUP_DATABASE_URL` | Railway: خدمة **Postgres** ← **Variables** ← `DATABASE_PUBLIC_URL` |
| `BACKUP_PASSPHRASE` | كلمة سرٍّ عشوائية من ٣٢ خانة فأكثر — من مولّد كلمات السرّ في متصفّحك مثلاً |

**احفظ `BACKUP_PASSPHRASE` في مكانٍ آخر أيضاً**، كمدير كلمات السرّ: GitHub لا
يُظهرها بعد حفظها، وبدونها لا تُفتح أي نسخة. والصور تُنزَّل من الخادم بعنوانه في
متغيّر المستودع `API_URL` — نفسه الذي عيّنته لنسخة APK.

ثم جرّبه: **Actions** ← «نسخة احتياطية للقاعدة» ← **Run workflow**. بعد العلامة
الخضراء تجد في أسفل صفحة التشغيل ملفّين: `db` و`uploads`.

**الإرجاع:**

١. **Actions** ← «نسخة احتياطية للقاعدة» ← افتح تشغيل اليوم الذي تريده، وانسخ الرقم
   في آخر رابطه: `…/actions/runs/الرقم`.

٢. **Actions** ← «إرجاع نسخة احتياطية» ← **Run workflow** ← الرقم و`نعم`.

٣. Railway ← خدمة الخادم ← **Deployments** ← ⋮ ← **Restart**.

- قبل المحو يأخذ الإرجاع نسخةً مما في القاعدة الآن ويحفظها مع تشغيله. فإن ندمت،
  أرجِع رقم تشغيل الإرجاع نفسه.
- المحو والإحلال معاً أو لا شيء: إن فشل شيءٌ بقيت القاعدة كما كانت.
- الصور لا تُرجَع بالزرّ: هي على قرص الخادم، ولا يصله GitHub. فقدُها نادر، ونسختها
  في `uploads` إن احتجتها.

وأمران:

- **المستودع عامّ:** ملفّات النسخ ينزّلها أيّ أحد، لذلك تُشفَّر قبل الرفع بـAES-256،
  وبلا كلمة السرّ لا تعني شيئاً. ولا يُطبع في سجلّ التشغيل شيءٌ من البيانات.
- **إن لم يتغيّر المستودع ستين يوماً** أوقف GitHub المهامّ المجدولة، ويراسلك قبلها.
  عندها افتح «نسخة احتياطية للقاعدة» واضغط **Enable workflow**.

## بعد الانتقال

| ماذا | كيف |
|---|---|
| تحديث الخادم | وحده: كل دمجٍ يمسّ `api/` يُبنى ويُنشر، والترحيل يجري عند الإقلاع |
| اللوحات ونسخة التطبيق | تُبنى وتُنشر وحدها مع كل دمج |
| النسخ الاحتياطي | كل ليلة عبر GitHub، مشفّرةً — القسم ٩ |
| الإرجاع من نسخة | **Actions** ← «إرجاع نسخة احتياطية» — القسم ٩ |
| سجلّ الخادم | خدمة الخادم ← **Deployments** ← **View logs** |
| الاستهلاك والفاتورة | صفحة **Usage** في Railway |
| نسيت باسوورد المالك | الخطوات أدناه |

**نسيت باسوورد المالك:** ثبّت [Railway CLI](https://docs.railway.com/cli) على جهازك
وادخل بـ`railway login`، ثم زرّ الفأرة الأيمن على خدمة الخادم ← **Copy SSH Command**،
والصقه في الطرفية. داخل الخادم:

```bash
cd /app && OWNER_EMAIL='بريدك' OWNER_PASSWORD='الباسوورد الجديد' npm run owner:reset
```

كل نشرٍ يوقف الخادم ثوانيَ: القرص الدائم لا يُركَّب في نسختين معاً، فتُطفأ القديمة
قبل أن تقلع الجديدة — كما على Render اليوم.

## إن لم يعمل شيء

- **النشر في Railway يفشل وسجلّه يقول «لا قرص دائماً للصور»:** القرص الدائم في
  الخطوة ٣، ومساره `/data/uploads` بالضبط.
- **`https://api.example.com/health` لا يفتح:** السجلّان في Cloudflare كما عرضتهما
  Railway حرفاً بحرف، وسجلّ `api` رماديّ. ثم انتظر علامة التحقق بجانب الدومين في
  Railway.
- **اللوحات تقول «تعذّر الاتصال بالخادم»:** إمّا `NEXT_PUBLIC_API_URL` خطأ في
  Cloudflare — صحّحه وأعد البناء (Deployments ← Retry deployment)، وإمّا دومين
  الموقع غائبٌ عن `WEB_ORIGIN` في Railway — أضفه ثم **Deploy**.
- **بناء Cloudflare يفشل برسالة عن `NEXT_PUBLIC_API_URL`:** المتغيّر غير معيَّن أو
  بلا `https://`.
- **سجلّ بناء Cloudflare فيه `npx wrangler deploy` ثم «Could not detect a directory
  containing static files»:** المشروع Worker لا Pages. احذفه (Settings ← Delete)
  وأنشئه من جديد من تبويب Pages.
- **زرّ النقل يفشل:** السبب بالعربية أعلى صفحة التشغيل، وقاعدة Railway لم تُمسّ. وأشهره:
  - سرٌّ غير معيَّن، أو رابطٌ داخليّ بدل الخارجي — انسخ الرابط من المكان في الجدول.
  - «تعذّر الاتصال بقاعدة Render»: صفحة القاعدة في Render ← **Networking** — يجب أن
    تقبل الاتصال من أي عنوان (`0.0.0.0/0`)، وهو الأصل فيها.
  - «قاعدة Railway أقدم إصداراً من Render»: خدمة **Postgres** في Railway ←
    **Database** ← **Config** ← **Major Version Upgrade** إلى إصدار Render، ثم أعد
    التشغيل.
- **الإرجاع يفشل عند تنزيل النسخة:** الرقم ليس لتشغيلٍ من «نسخة احتياطية للقاعدة» أو
  «إرجاع نسخة احتياطية»، أو مضى عليه أكثر من تسعين يوماً.
- **صورٌ لا تظهر بعد النقل:** سجلّ الخادم بعد **Restart** يذكر ما تعذّر منها. ما ردّ
  عليه Render بـ404 مفقودٌ هناك أيضاً، وغيره يُعاد بـ**Restart** آخر ما دام Render
  يعمل.

## لماذا هكذا

- **Railway:** خادمٌ وقاعدة مُداران كما على Render — نشرٌ من GitHub ونسخٌ احتياطية
  بلا إدارة خادم — وبكلفةٍ أقل بكثير.
- **اللوحات ملفّاتٌ ثابتة على Cloudflare:** الصفحات كلها تجلب بياناتها في المتصفّح،
  فلا تحتاج خادماً. تُبنى مرّة وتُخدم من شبكة Cloudflare مجاناً.
- **الخادم في حاوية (`api/Dockerfile`):** تبنيها Railway في كل نشر، وعند إقلاعها
  (`api/scripts/container-start.sh`) ترحّل القاعدة وتعبّئها كما يفعل Render اليوم.
- **الصور على قرصٍ دائم:** الشفرة تكتبها على القرص أصلاً (`UPLOAD_DIR`)، فلم يتغيّر
  فيها سطر.
- **النقل من GitHub:** بلا تثبيتٍ على جهازك، والنسخة تفنى مع جهاز التشغيل المؤقّت.
- **النسخ الاحتياطي في GitHub:** مجاناً، وخارج Railway — إن ضاع شيءٌ فيها بقيت النسخ.
- **صفحة الطبيب صار رابطها `/doctors/profile?id=…`** بدل `/doctors/<id>`: اللوحات
  ملفّاتٌ ثابتة تُبنى مرّة، والأطباء يُسجَّلون كل يوم بعدها. والروابط القديمة التي
  شاركها المرضى تُحوَّل إلى الجديدة تلقائياً على Render حتى الانتقال.
